# Documentation Guidance

- `PRODUCT.md` records owner-approved intent; `MODES.md` and
  `BACKEND_ARCHITECTURE.md` describe the current implementation and its seams.
- Label proposed, implemented, locally verified, and deployed behavior accurately.
  Code inspection does not verify a deployed account.
- Keep obsolete proposals/work logs in `history/` with a clear status notice.
  Do not turn their suggestions or completion claims into current instructions.
- Prefer links to canonical rules over copied checklists. Maintain `README.md`
  as the documentation map and check relative links when moving documents.
- Keep experiments lightweight; a short conversation brief is enough unless
  a durable decision or non-obvious contract needs recording.
- Do not add model IDs, resource names, credentials, or machine-specific paths
  from an environment observation to general setup guidance.
